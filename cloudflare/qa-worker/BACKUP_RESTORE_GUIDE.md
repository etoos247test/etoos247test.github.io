# 이투스247 질문 시스템 백업·초기화·복원 운영 안내

## 1. 현재 보존 정책

- 마스터 계정: 학년도 초기화에서 유지
- 현재 승인 교사 계정: 로그인 UID, 활성 상태, 소속관, 질문·학생관리 권한을 유지
- 학생 계정과 학생 승인 기록: 학년도 초기화에서 삭제
- 미승인 교사 요청: 학년도 초기화에서 삭제
- 질문과 답변: 질문을 `종료`한 시각부터 7일 뒤 자동 삭제
- 질문 첨부사진: 질문 삭제 시 R2 원본과 D1 메타정보를 함께 삭제
- 마스터 수시 삭제: 마스터 화면의 `질문 자동삭제·수시 삭제`에서 즉시 삭제 가능
- 연간 백업 사진 사본: 비공개 R2 백업 경로에 30일 보관 후 자동 삭제
- 공지 사진: Firebase Storage에 저장하며 마스터가 공지 글을 유지한 채 개별 또는 전체 삭제 가능

## 2. 학년도 초기화 전 백업

1. `/question-access/`에 마스터 계정으로 로그인한다.
2. `교사 승인·권한 관리` 아래의 `학년도 백업·초기화`를 연다.
3. 새 학년도를 네 자리로 입력한다.
4. `1단계 삭제 대상 확인`을 누른다.
5. 삭제 예정 학생, 신청, 질문, 답변, 사진 건수를 확인한다.
6. 화면에 표시되는 확인 문구와 6자리 번호를 다시 입력한다.
7. `2단계 암호화 백업 실행`을 누른다.
8. 다음 두 결과가 모두 완료될 때까지 기다린다.
   - D1 자료: gzip 압축 후 AES-256-GCM 암호화하여 GitHub `backups/qa/{학년도}/`에 저장
   - 질문 사진: 비공개 R2 `backups/annual/{backupId}/r2/`로 복사
9. GitHub 백업 경로와 R2 사진 복사 건수를 확인한다.
10. `백업 확인 후 초기화`를 누른다.

초기화는 백업 완료 전에는 실행되지 않는다.

## 3. 초기화 후 유지되는 정보

다음 정보는 유지된다.

- QA 마스터 계정
- 현재 승인 교사 Firebase UID
- 승인 교사 이메일과 이름
- 승인 교사 활성·중지 상태
- 승인 교사 수성1관·수성2관 소속
- 질문 답변 권한
- 학생 승인 권한
- 학생정보 관리 권한

다음 정보는 삭제된다.

- 학생 계정과 학생번호
- 학생 가입 신청과 승인 이력
- 미승인 교사 요청
- 질문, 답변, 재질문, 피드백
- 질문 첨부사진 원본
- 질문 관련 일반 감사기록

## 4. 백업 복원 방법

1. `/question-access/`에 마스터 계정으로 로그인한다.
2. `학년도 백업·초기화`의 `백업 목록·복원`을 연다.
3. `GitHub 백업 목록 불러오기`를 누른다.
4. 복원할 학년도와 백업 ID를 선택한다.
5. `1단계 복원 내용 확인`을 누른다.
6. 복원할 사용자, 질문, 메시지, 첨부 메타정보 건수를 확인한다.
7. 화면에 표시되는 복원 확인 문구와 6자리 번호를 다시 입력한다.
8. `2단계 백업 복원 실행`을 누른다.
9. 다음 순서의 진행률을 확인한다.
   - 현재 질문 사진 정리
   - R2 백업 사진 복원
   - D1 사용자·질문·메시지·첨부 메타정보 복원
10. 완료 후 화면을 새로고침하고 학생·교사·질문 목록을 확인한다.

## 5. 복원 시 승인 교사 처리

복원으로 과거 질문과 답변 작성자를 재구성하더라도, 현재 승인 교사의 로그인과 권한을 우선 유지한다.

- 현재 승인 교사와 같은 UID: 현재 권한으로 다시 적용
- 과거 백업에만 있는 교사: 질문 작성자 참조를 위해 계정 행은 남길 수 있으나 활성 상태와 관리 권한은 해제
- 현재 승인 교사 소속관과 권한: 복원 완료 후 현재 설정으로 다시 적용

## 6. 사진 복원의 시간 제한

연간 백업 사진 사본은 R2에 30일 동안 보관한다.

- 백업 후 30일 이내: D1 자료와 질문 사진을 함께 복원 가능
- 백업 후 30일 초과: GitHub의 암호화 D1 백업은 남아 있어 글 자료 복원은 가능하지만, R2 사진 사본은 이미 삭제됐을 수 있음

장기 사진 보존이 필요한 학년도는 30일 안에 NAS 또는 별도 장기 저장소로 복사해야 한다.

## 7. 질문 자동삭제와 마스터 수시 삭제

질문이 `종료`되면 `closed_at`이 기록된다. 매일 실행되는 Cloudflare 예약 작업이 종료 후 7일이 지난 질문을 찾아 삭제한다.

자동삭제는 내부적으로 100건씩 나누어 처리하지만, 하루 총 삭제량을 100건으로 제한하지 않는다.

```text
만료 질문 250건
→ 1차 내부 배치 100건
→ 2차 내부 배치 100건
→ 3차 내부 배치 50건
→ 같은 예약 실행에서 전체 처리
```

각 배치는 `closed_at`과 질문 ID 순서로 이어서 조회한다. 특정 질문의 R2 또는 D1 삭제가 실패하면 그 질문만 실패기록에 남기고 나머지 만료 질문은 계속 처리하며, 실패한 질문은 다음 예약 실행에서 다시 시도한다.

삭제 범위:

- questions
- messages
- attachments 메타정보
- R2 질문 사진 원본

마스터는 7일을 기다리지 않고 `질문 자동삭제·수시 삭제`에서 질문별 `지금 삭제`를 사용할 수 있다.

## 8. 공지 사진 수시 삭제

`/academy-board/`에서 QA 마스터로 로그인하면 페이지 아래에 `마스터 공지 사진 관리`가 나타난다.

- 사진 1장만 삭제
- 해당 공지 사진 전체 삭제
- 공지 제목과 본문은 유지
- Firebase Storage 원본과 Firestore 사진 연결정보를 함께 정리

## 9. 복원 전 확인사항

복원은 현재 운영자료를 백업 시점 자료로 교체하는 작업이다.

- 현재 자료가 필요하면 먼저 별도 백업을 실행한다.
- GitHub 백업 파일을 임의 수정하지 않는다.
- `BACKUP_ENCRYPTION_KEY`를 잃으면 기존 암호화 백업을 복원할 수 없다.
- R2 사진 보존기간 30일을 넘겼는지 확인한다.
- 복원 완료 후 현재 승인 교사 권한과 소속관을 다시 확인한다.
