역할별 권한관리 구축안

학생은 화면상 로그인 절차 없이 자신의 전용 링크를 인증하고, 교사는 Google 계정으로 로그인합니다. 학생별·과목별·교사별 접근권한은 Firebase Authentication과 Security Rules로 제한합니다.

현재 · 설계 문서Firebase 프로젝트 미연결실제 로그인 미가동마스터 키 미발급
중요Firebase 설정값 중 웹용 공개 구성값은 클라이언트 코드에 존재할 수 있지만, 서비스 계정 비밀키·교사 마스터 키·학생 토큰 원문은 GitHub에 넣지 않습니다. 실제 권한 부여와 토큰 검증은 Cloud Functions 또는 Admin SDK가 실행되는 서버 영역에서 처리합니다.

2. 학생은 ‘로그인 화면 없이’ 어떻게 인증되는가

로그인 화면을 보여주지 않는 것과 인증 없이 공개 쓰기를 허용하는 것은 다릅니다. 학생 링크를 서버에서 확인한 뒤 학생 전용 Firebase 사용자로 자동 로그인시키는 방식이 안전합니다.

01

전용 링크 접속

M001과 무작위 링크토큰을 읽습니다.

02

Cloud Function 검증

토큰 해시·학생 활성상태·과목을 확인합니다.

03

Custom Token 발급

studentId와 math 권한이 포함된 일회성 로그인 토큰을 반환합니다.

04

자동 로그인

학생에게 로그인 UI를 보이지 않고 질문화면을 엽니다.

학생 인증 클레임 예시 { "role": "student", "subject": "math", "studentId": "M001", "active": true }

3. 교사 로그인과 마스터 키

권장 흐름

  1. 교사가 학원 지정 Google 계정으로 로그인
  2. 최초 1회 수학교사 등록키 입력
  3. Cloud Function이 키 해시·만료·사용여부 확인
  4. 해당 Firebase UID에 mathTeacher 권한 부여
  5. 등록키는 사용 완료 처리
  6. 이후 Google 로그인만으로 접속

마스터 키 원칙

  • 공용키 장기 사용 금지
  • 교사별 또는 1회용 등록키 사용
  • 키 원문을 HTML·Firestore 공개문서에 저장 금지
  • 서버에서 해시값으로 비교
  • 만료일·사용자·사용시각·폐기상태 기록
  • 퇴사 시 사용자 비활성화와 권한 회수
교사 Custom Claims 예시 { "role": "teacher", "subject": "math", "active": true } 총관리자 예시 { "role": "rootAdmin", "active": true }

6. Firestore 보안규칙 방향

규칙은 화면에서 버튼을 숨기는 수준이 아니라, 데이터베이스가 요청 자체를 거부하도록 작성해야 합니다.

개념 예시 — 실제 배포 전 Emulator 테스트 필요 rules_version = '2'; service cloud.firestore { match /databases/{database}/documents { function signedIn() { return request.auth != null; } function active() { return request.auth.token.active == true; } function isMathTeacher() { return signedIn() && active() && request.auth.token.role == 'teacher' && request.auth.token.subject == 'math'; } function isOwner(studentId) { return signedIn() && active() && request.auth.token.role == 'student' && request.auth.token.studentId == studentId; } match /questions/{questionId} { allow create: if isOwner(request.resource.data.studentId) && request.resource.data.subject == 'math'; allow read: if isOwner(resource.data.studentId) || isMathTeacher(); allow update: if isMathTeacher(); allow delete: if request.auth.token.role == 'rootAdmin'; } } }

7. 문제 사진 Storage 규칙 방향

학생 업로드

  • 경로: questions/math/M001/질문ID/사진
  • 학생 claim의 studentId와 경로 일치
  • 이미지 MIME만 허용
  • 파일 크기 제한
  • 질문당 사진 수 제한은 서버에서도 재검사

교사 열람

  • 수학 교사 claim이 있는 계정만 열람
  • 공개 다운로드 URL 장기 노출 금지
  • 답변 완료 후 보관기간 적용
  • 삭제 작업은 책임자·관리자만 허용
  • 사진 경로를 질문 문서와 연결
개념 예시 service firebase.storage { match /b/{bucket}/o { match /questions/math/{studentId}/{questionId}/{fileName} { allow write: if request.auth != null && request.auth.token.role == 'student' && request.auth.token.studentId == studentId && request.resource.size < 5 * 1024 * 1024 && request.resource.contentType.matches('image/.*'); allow read: if request.auth != null && (request.auth.token.studentId == studentId || (request.auth.token.role == 'teacher' && request.auth.token.subject == 'math')); } } }

8. App Check와 도배 방지

App Check

정상 웹 앱에서 발생한 요청인지 확인하는 추가 방어층으로 사용합니다. 보안규칙과 대체 관계가 아니라 함께 적용합니다.

Cloud Function 제한

학생별 분당·일일 등록 수, 중복내용, 토큰 실패횟수, 이미지 수를 서버에서 제한합니다.

링크 재발급

학생 링크가 노출되면 tokenHash를 변경하고 기존 링크 인증을 즉시 거부합니다.

수학 100명만 빠르게 시험하려면 Apps Script가 가볍습니다. 그러나 학생별 본인 질문 조회, 여러 교사의 동시 답변, 국어·영어 확장, 접근기록과 권한회수가 중요하다면 Firebase 방식이 장기 구조로 더 적합합니다.
