# 학생 로그인 계정 규칙 — 수성1관·수성2관

## 학생코드 배정

학생코드는 소속관별로 첫 글자를 다르게 사용한다.

| 소속관 | 학생코드 범위 | 최대 인원 |
|---|---:|---:|
| 수성1관 | `M001~M199` | 199명 |
| 수성2관 | `S001~S199` | 199명 |
| 전체 | M·S 합산 | 398명 |

학생코드 첫 글자 자체가 소속관을 나타낸다.

```text
M = 수성1관
S = 수성2관
```

## 로그인 입력

학생 로그인 화면에는 다음 세 값을 노출한다.

1. 소속관: 수성1관 또는 수성2관
2. 학생코드: M001~M199 또는 S001~S199
3. 비밀번호

소속관 선택은 학생과 관리자가 입력 상태를 쉽게 확인하기 위한 표시·검증 항목이다. 실제 Firebase 로그인 계정과 중복 판단은 학생코드 하나를 기준으로 한다.

예:

```text
수성1관 선택 + M023 → 정상
수성2관 선택 + S023 → 정상
수성1관 선택 + S023 → 입력 불일치로 차단
```

## 내부 Firebase Authentication 이메일

학생 화면에는 이메일을 노출하지 않는다. 프로그램이 학생코드를 내부 이메일로 변환한다.

| 학생코드 | 내부 이메일 |
|---|---|
| M001 | `m001@etoos247test.local` |
| S001 | `s001@etoos247test.local` |

따라서 M001과 S001은 서로 다른 계정이며, 같은 학생코드는 한 번만 사용할 수 있다.

## 중복 판단

중복 기준은 다음 하나이다.

```text
studentId
```

허용:

```text
M001
S001
```

차단:

```text
M001
M001
```

## 계정 생성 권한

학생 계정은 다음 사용자만 생성할 수 있다.

- 활성 마스터
- `canApproveStudents: true`인 활성 교사
- 학생코드로 판정된 소속관이 해당 교사의 `allowedCampuses`에 포함된 경우

예를 들어 수성1관만 승인받은 준마스터는 M001~M199 계정만 생성할 수 있다. S코드를 입력하면 서버에서 차단한다.

## 생성 데이터

Firebase Authentication 계정을 만든 뒤 Firestore에 다음 문서를 함께 생성한다.

```text
users/{학생 UID}
role: student
active: true
campus: suseong1 또는 suseong2
studentId: M001 또는 S001
name: 학생 이름
email: 내부 이메일
loginKey: M001 또는 S001
mustChangePassword: true
```

## 학생정보 수정과 관 이동

학생코드·이름을 수정할 때 Firebase Authentication 이메일과 Firestore 학생 문서를 함께 변경한다.

관을 이동하면 숫자는 유지하고 첫 글자를 바꾼다.

```text
수성1관 M023 → 수성2관 S023
수성2관 S057 → 수성1관 M057
```

변경된 학생코드가 이미 사용 중이면 이동을 차단한다. 기존 질문의 소속관·학생코드·학생 이름도 함께 갱신한다.

## 배포

웹 화면은 GitHub Pages로 배포된다. 실제 계정 생성·학생코드 변경·비밀번호 재발급은 Cloud Functions를 Firebase 프로젝트에 배포한 뒤 작동한다.

```bash
firebase deploy --only functions
```
